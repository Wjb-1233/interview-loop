# 面试官视角测试与创新建议

## 结论

项目已具备支撑毕业设计演示的完整训练闭环。本轮重新执行回归、读取真实页面，并通过隔离诊断复现了四类可改进边界。现在最有价值的方向是提升面试判断与效果验证：问题为何追问、哪些能力有回答支撑、学习后能否独立解决新问题。

以下是参照资深面试官工作方式的产品评估，不是声称作者有十年真实招聘经历，也不把自动化测试结果解释为模型专业判断已达到真人水平。本轮没有修改业务代码、历史训练、成绩、计划或缓存视频。

## 2. 已复现，应先修的边界

### P1：提示卡可能提前跳到下一题

复现：为隔离场次设置两道必问题，模型替身严格按本轮 planned question 提问。当前题为“请解释数据库事务隔离原理？”，点击提示卡，接口返回“项目中如何处理接口超时？”。

原因：提问后 covered_count 已推进，`training/service.py:session_hint` 又用 bank[covered_count] 作为正在回答的问题。这个指针表示后续待提问项，不能同时当成当前题 ID。

改进：提示卡以当前实际 AI 问题及其关联考察点为准；题型决定提示结构。知识题提示定义、机制和边界，经历题提示个人行动与结果。

验收：开场、第一道必问题、中间题、重复问题、所有必问题结束后，提示题目均与页面当前题对应。

### P1：请求重复问题会污染表达统计与客观配对

复现：回答一轮 → 输入“请再说一遍” → 再回答一轮 → 结束。

| 项目 | 结果 |
| --- | --- |
| 正式答题轮数 | 2 |
| answerTurns 问答数 | 2 |
| speechStats.rounds | **3** |
| objective.compute 收到的回答数 | **3，包含请求重复** |
| 客观指标使用的问答与标准投影 | **不一致** |

原因：问答投影与有效证据已经使用 answer_turns，但评分服务的客观指标仍分别取全部 AI/USER 消息，speech_statistics 也取全部 USER 消息。

改进：评分输入、统计与提示参考都消费正式问答；控制指令保留在对话记录中，独立标记，不作为答题质量样本。重听与澄清能力可单列训练观察。

边界：目前只有表达干净维度直接混入重复度锚点，其余客观指标主要进入模型提示；此诊断证明输入和统计有误，没有证明真实模型最终一定扣了多少分。

### P1：专业核查与评分缺少自洽性保护

这是**合成模型响应注入测试**，不是声称真实模型实际给过这样的成绩。

注入响应：四维均 5 分、有效原话证据齐全，同时 technicalChecks 将同轮原话标记为 ERROR。服务端接收后返回 **100 分、VERIFIED、eligibleForGrowth=true**。

改进：把“原话引用校验”“专业内容核查”“评分与核查结果是否一致”分开检查。遇到明确错误与最高档评价冲突时，按该错误的重要性触发解释校验或一次复核；未解决的冲突暂不作为正式成长样本。不要将任何小错误机械映射为整场固定零分。

验收：重要专业错误、局部非关键错误、UNCERTAIN、已被候选人纠正的错误分别测试；复核失败应保留可读报告并说明状态。SQL 和报告的统计资格同时更新。

### P2：关键词标签缺少否定和引用语境

已复现：

- “我不会说‘不关我的事’，而是先核实影响并主动协调解决。”被标为 **推卸责任**。
- “我不紧张，已经准备好了。”被判断为 **紧张**。

另外，“我不知道当前环境的隔离级别，不能直接承诺，需要先查配置并用并发测试验证。”的规则 evasiveRatio 为 1.0。这里只证明规则把它视为回避信号，没有证明真实模型最终扣分。

改进：先处理否定、引用与反思语境；区分“无回答”与“说明未知范围并提出验证步骤”。规则不确定时不显示确定性标签。保留原话和触发依据便于复核。

## 3. 已有能力，不能重复当新功能

当前已经有简历/JD 定制问题、三层追问、压力面、深挖模式、四维原话证据、专业核查区、Elo 难度推荐、同题历史、微课回看、同条件复测和看板总结。

因此，“增加三层追问”“增加微课”“增加同题对比”“增加可爱人物”都不是本项目下一阶段最有说服力的创新。继续优化现有模块的判断机制和实验依据更合适。

## 4. 最值得新增的三个方向

### 1. 根据证据缺口决定下一问

当前三层追问主要由提示词约束，内容阶段主要按轮次推进。建议为每个考察点保存明确状态：只提及、已解释、给出验证、存在待澄清矛盾、尚未覆盖；下一问针对一个缺口，回答已充分时进入下一点。

例：候选人说“做缓存后延迟降低 40%”。面试官依次确认基线与指标 → 个人改动 → 验证方式 → 新增约束。若对方已经解释压测条件，就不再重复问“怎么验证”；若先说团队成果，继续区分本人职责。

报告在相关原话旁解释“这一问要确认什么、目前还缺什么”，展示结构化考察依据，不展示模型内部思维链。前后数字不一致时先邀请澄清，不把差异自动认定为造假。

落点：复用训练状态、问答 ID 和现有报告，不增加独立导航。先在文字训练验证，再扩展到实时语音，控制额外模型调用和延迟。

验收：充分/模糊/主动承认未知/前后需要澄清的回答各建固定样例，记录重复追问率、关键考察点覆盖、无依据问题率与每轮延迟，和当前提示词方案对照。训练模式可自适应；需要比较的测评模式固定核心题、追问预算与评分标准。

### 2. 增加岗位能力证据矩阵

四维表达继续保留。另在现有报告中按岗位展示“专业点是否已被回答支撑”，例如后端岗位的事务、索引、缓存一致性、故障定位，产品岗位的需求取舍、指标设计与实验验证。

每个专业点展示：已解释的原话、缺少的关键要点、可接受的不同方案、待核查项。状态用“已体现 / 证据有限 / 未考察 / 待确认”，避免把未被提问误写成不会，也不把它们简单平均成新的万能总分。

落点：在现有场景管理中，为重点问题增加考察要点、适用条件、典型误区和资料版本。先做一个目标岗位和少量核心题；专业参考由教师/领域人员核对。可以直接存结构化数据，不需要恢复独立题库入口或 Milvus。

验收：准确答案、术语堆砌但错误、不同有效方案、明确承认未实操四类输入盲评。检查要点支持是否准确、错误标记是否有根据、不同方案是否被合理接纳。

### 3. 训练后用陌生题验证迁移

当前同题复测能帮助核对改写后的表现。建议在同题巩固之后，增加一道同能力但更换约束、候选人未提前看过的问题，单独报告独立应用情况。

例：训练使用“数据库扣库存”，迁移题改为“优惠券核销”；继续考察并发、幂等与验证，但不提供原题改写或即时提示。结果显示“原题能完成”“新约束下能独立应用”“仍需哪些帮助”。

落点：复用现有计划末尾的练习流程，分别保存练习与测评模式、提示使用和题目版本；没有必要重新添加用户已移除的看板卡片。

验收：先准备同能力、难度相近的多组题，经人工核对后随机分配；与同题复测分别报告结果。新题成绩不能直接接到原同题趋势线上，几道题分数变高也不能自动解释为真实招聘通过率提高。

## 5. 可选补充：反问与需求澄清

面试还可以训练主动确认约束，以及候选人向面试官提出问题。让用户针对模糊需求先问清目标、资源和限制；结束前练习了解职责、协作和成功标准。评价问题是否有助于决策，不按问题数量或表现强势程度加分。

这是实用扩展，但建议排在上述三项之后。不要把专业紧张程度、人物表情或镜头注视自动解释为胜任力。

## 6. 支撑论文与答辩的实验

仓库已有人工标注导出与一致性统计脚本，本轮在源码和文档范围未找到已完成的人工评分对照报告。

建议先收集 20–30 份真实或明确标注为合成的回答，覆盖好/中/差、流畅但专业错误、简短但正确、诚实未知、套话和重复请求。由独立评分者按同一标准评分，再运行模型；至少报告四维 MAE、排序一致性、原话引用正确率、重要错误识别情况和重复评分波动。记录模型、规则和题目版本。

样本量用于初步诊断，不代表获得普遍有效的招聘预测模型。不要用自己编出的人工分数证明系统准确，也不要把微课生成的参考回答同时当作独立测试答案。

可以设计三组工程实验：当前提示词追问 vs 证据状态驱动；纯模型核查 vs 有人工维护要点的核查；同题复测表现 vs 独立新题表现。先定义指标，再报告结果，不预设新方案一定更好。

结构化面试强调岗位相关考察与统一评分标准，见 [OPM 的结构化面试说明](https://www.opm.gov/policy-data-oversight/assessment-and-selection/structured-interviews/)。本文据此建议在训练与测评中明确模式和规则，未将自适应训练等同于标准化选拔。

LLM 评委存在位置、长度和自偏好等已被研究讨论的偏差，见 [Zheng 等人的原始研究](https://arxiv.org/abs/2306.05685)。这是补人工盲评和对照的理由，不是已经证明当前所用模型存在某个特定误差率。

## 7. 推荐顺序

1. 修复本轮复现的提示卡、非答题消息统计、评分自洽性和语境标签。
2. 以一个岗位为样板实现证据缺口驱动追问。
3. 在现有训练计划中加入新题迁移验证。
4. 补齐岗位能力证据矩阵和人工对照实验。

论文可围绕“证据驱动的自适应追问与迁移验证”描述工程创新；实际贡献以实现、对照实验与失败分析为依据，不宣称未经验证的学术首创或录用概率。
