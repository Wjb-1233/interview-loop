# 开发接手指南

本文描述当前实现。历史审计用于解释改造原因；修改业务时先看这里，再沿用例查代码。

## 1. 启动与阅读顺序

安装、环境变量与迁移见 [启动指南](启动指南.md) 和 [README](../README.md)。密钥只放在 Git 忽略的 `.env`，不要把运行日志中的令牌复制到文档。

默认前端端口是 5173，本次本机验收使用 **5175**，后端使用 **8081**；Vite 可能因端口占用递增，排障时先确认进程对应的工作目录。MySQL、Redis 的本机端口是 3308、6380。

建议按下面顺序读，不必从大服务文件逐行开始：

1. `frontend/src/router.ts`、`backend/app/main.py`：页面与功能域入口。
2. 本文词汇表、`training/policy.py`、`training/answer_turns.py`：业务门槛与问答契约。
3. `training/workflow.py` → `evaluations/service.py`：结束训练与报告持久化。
4. `evaluations/quality.py` → `dashboard/service.py`、`dashboard/summary.py`：哪些报告进入成长看板。
5. `plans/service.py`、`plans/lesson_videos.py`：计划任务、微课快照与已有视频回看。
6. 前端下表中的对应模块；最后再读实时引擎的原始协议。

后端路径均相对于 `backend/app/features/`，前端路径相对于 `frontend/src/`。

## 2. 词汇与兼容约定

| 名称 | 含义与注意事项 |
| --- | --- |
| TrainingSession / attempt | 一次训练尝试。FINISHED 只表示训练结束，报告生成仍可能失败。 |
| channel | TEXT、VOICE、VIDEO，表示答题通道。 |
| mode | 服务端 STANDARD / DRILL，表示训练策略。旧链接的 `?mode=voice` 是输入方式参数，仍兼容。 |
| inputMode / captureMode | 前端输入方式 text/voice，以及实时房间 voice/video；不要与训练策略混用。 |
| depth | 训练强度，不是训练状态。 |
| stage / RoomPhase | 前者是面试内容阶段；后者是实时房间连接与运行阶段。 |
| logic / relevance | 内容与逻辑 / 贴合问题。 |
| correctness / concision | 信息完整 / 表达干净。保留原 API 键和数据库列；专业内容核查单列在 technicalChecks。 |
| degraded | 模型不可用等导致使用本地参考结果；不等于所有质量状态。 |
| qualityStatus | VERIFIED、PENDING_RESCORE、RULE_BASED、LIMITED_SAMPLE、INSUFFICIENT_EVIDENCE。定义在 evaluations/status.py。 |
| eligibleForGrowth | 是否满足成长统计资格；不要仅根据 degraded 或总分自行判断。 |
| uploadedSessionId | 已提交答案的会话 ID，供报告失败后重试复用；不是第二场训练。 |
| validated_plan_tasks | 校验 v2 计划任务并保留额外元数据的副本，不推断来源、不生成内容。normalized_tasks 仅保留旧导入兼容。 |

### 三个不同门槛

`training/policy.py` 是后端门槛的入口：至少 **1 轮**可总结；至少 **2 轮**才可能成为成长样本，另须满足证据等资格；计划任务达标一般 **6 轮**，VIDEO **2 轮**。提前结束可有报告，但不代表计划任务达标。

### 问答配对

旧数据中 TEXT 的 USER(n) 回答 AI(n−1)，VOICE/VIDEO 的 USER(n) 回答 AI(n)。不要给历史 round_no 批量加减一。

`answer_turns(messages, channel)` 返回明确的题目、回答与答题轮次，同轮重复提示不覆盖原回答。报告证据、题型、同题比较都使用这一规则。消息查询先用 `message_order.dialogue_order` 排序，以处理同时间戳和重复发言。

会话响应增加只读 `answerTurns` 投影，保留原 `messages`。前端 `lib/answerTurns.ts` 优先消费投影，对旧响应保留兼容读取；新功能不再各算一遍 n−1。

## 3. 用例、写入与失败边界

| 用例 | 入口与归属 | 副作用 / 失败后状态 |
| --- | --- | --- |
| 文字答题 | TrainingView → useTrainingSession → training/service.py | 保存用户回答和模型回复，推进内容阶段。草稿仅属于当前场次。 |
| 直接退出 | useInterviewExit → activeTrainingAttempt → discard 接口 | 丢弃未明确保留的本场记录，不评分、不生成计划。清理失败停留并允许重试。注销顺序是清理 → 清除认证 → 跳转。 |
| 结束训练 | training/workflow.py:end_training_attempt | 先保存 FINISHED，再调用评分；模型请求不包在一个长事务里。报告失败保留训练，允许重试。 |
| 生成报告 | evaluations/service.py:evaluate_session | 评分策略在 scoring.py，报告投影在 report_queries.py，计划生成在 plan_builder.py。报告、证据与条件性计划在末尾提交。 |
| 重评 | evaluations/service.py | 复用报告 ID，成功后保存旧版本并替换证据；模型失败保留原报告。首次结果才更新能力并按条件建计划。 |
| 原计划任务收尾 | training/workflow.py → plans/service.py | 独立检查任务轮数等条件；提前结束的报告仍可读，未达标任务保持未完成。 |
| 实时训练保存 | LiveInterviewRoom → useInterviewSubmission | 等待录制最后数据块后上传，随后请求 finish。上传成功但报告失败时复用已上传 ID，重试不重复传文件。 |
| 成长统计 | evaluations/quality.py → dashboard | 只读。Python 与 SQL 两条资格判断保留，用契约测试验证一致；不能全量加载后过滤分页结果。 |
| 微课回看 | plans/lesson_videos.py:get_lesson_video | GET 只读现有状态和缓存，不调用视频生成。课程正文是计划内固定快照。 |
| 显式生成微课 | plans/service.py:personalized_lesson | POST 才可能生成并提交。已有学习步骤、已完成或非 ACTIVE 计划会保护原快照，force 也不能覆盖已学习内容。来源缺失时仍保留现有最近报告回退策略。 |

明确点击结束以后，离页会保留本次训练与总结；FINISHED、已请求保留、报告已存在是不同事实，不应只用一个布尔值替代。

## 4. 前端职责地图

| 文件 | 唯一主要职责 |
| --- | --- |
| App.vue / lib/activeTrainingAttempt.ts | 每个应用实例拥有一个当前训练清理控制器；页面登记与注销，认证模块不依赖训练。 |
| main.ts | 首次路由准备好后挂载页面，避免在训练 ID 未确定时提供注销按钮。 |
| composables/useInterviewExit.ts | 离页守卫、关闭页面清理、草稿释放及清理失败提示。 |
| components/training/LiveInterviewRoom.vue | 连接与设备调度、原始协议事件、用户操作与展示。 |
| composables/useInterviewPlayback.ts | PCM 播放、播放队列、重听、AudioContext 和人物口型音轨。 |
| composables/useInterviewRecording.ts | MediaRecorder、数据块、等待最终 stop 边界。 |
| composables/useInterviewSubmission.ts | 答案上传、报告生成与已上传内容重试。 |
| composables/useTrainingReport.ts | 报告与会话加载、重评及加载错误。 |
| composables/useReportSharing.ts | 分享链接签发、复制、打印入口及撤销。 |
| components/report/ReportSelfReview.vue | 逐题自评表单与保存；失败通过 error 事件交给页面显示。 |
| lib/contracts/trainingMetadata.ts | 稀疏媒体观测、自评和转写字段；没有音频指标不表示指标为零。 |

设备序号、迟到流释放、AudioContext 恢复和最终录制块均有真实用途。Live2D 使用本地模型；暂停、打断、离页要停止声音和动作，不要为统一封装删去这些边界。

## 5. 数据与历史边界

核心关系：用户 → TrainingSession → Message / Evaluation → EvaluationEvidence；TrainingPlan.tasks 保存来源、课程快照与学习进度，媒体文件和视频缓存另存。简历文字仅属于该场训练。

- 数据库保存业务状态；Redis 只负责限流，没有训练状态缓存或后台评分队列。
- 旧分析任务保留只读结果；退休的视频上传入口返回 410，当前音视频训练走 `/voice/sessions`。
- 迁移 20261117_0048 将计划任务固化为 v2。GET 不补任务、不换来源；不要重新引入运行时迁移。
- appropriateness 旧列、历史英语记录和旧微课缓存仍为历史读取保留，不代表恢复对应新功能。
- 本轮重构没有数据库迁移、历史轮次重写或视频重新生成。暂不拆 delivery JSON、重命名数据库分数字段或移除 LangGraph。

## 6. 验证入口

在 `backend` 运行离线回归：

```powershell
.\.venv\Scripts\python.exe -m pytest -q
```

`tests/conftest.py` 使用独立临时数据库并禁止真实模型调用。公共客户端、认证、示例和模型替身在 `tests/support/`；不要从 test_* 模块导入公共函数。模型替身匹配导出的提示常量，修改提示时同时核对输入输出契约。

在 `frontend` 运行构建与当前服务上的浏览器回归：

```powershell
npm run build
$env:PW_CHANNEL = 'msedge'
$env:E2E_BASE = 'http://127.0.0.1:5175'
npx playwright test e2e/interview-exit.spec.ts e2e/video-immersion.spec.ts e2e/report-review.spec.ts e2e/dashboard-growth.spec.ts e2e/admin-content.spec.ts e2e/course-replay.spec.ts
```

上列浏览器测试通过接口替身验证异常、重试和交互，部分使用真实本地 Live2D 与媒体夹具；不能据此声称真实 ASR、模型、麦克风与摄像头端到端全通过。`upgrade.spec.ts` 等其他套件有独立服务要求，见各测试及 [功能升级与验收](功能升级与验收.md)。

真实模型、设备和本地数据验证必须单独进行并记录是否产生数据或费用。改评分优先跑问答契约、证据、重评和成长资格；改媒体优先跑权限拒绝、录制收尾、打断、退出与报告失败重试。

## 7. 接手自测

接手者应能解释：一轮报告为何不进趋势；结束请求依次提交什么；文字与视频第一题如何配对；报告失败为何不应重新上传录音；旧微课回看为何不能发生成请求。需要背景时再查 [认知成本审计](archive/接手认知成本与简化方案-2026-11-17.md) 与 [历史清理验收](archive/历史包袱清理验收-2026-11-17.md)。
