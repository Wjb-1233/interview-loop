## 1. P1：音视频的逐轮转写编辑链路没有接上

复现：分别通过当前 `/voice/sessions` 接口保存两轮 VOICE/VIDEO 回答，结束后获取会话与报告。

| 通道 | 已保存的问答 | 可编辑转写条目 | 修正第一轮接口 |
| --- | --- | --- | --- |
| VOICE | 2 | 0 | 404 |
| VIDEO | 2 | 0 | 404 |

隔离浏览器也确认：报告展示两轮对话回放，但 `.transcript` 编辑区数量为 0。

原因：保存流程记录 `Message`，没有建立 `delivery.transcript`；本地音频分析返回统计、全文与单词时间，而非逐轮编辑列表。报告和修正接口却只消费 `delivery.transcript`。目前部分测试手动预置该字段，因此没有覆盖“实际保存 → 进入报告 → 修正”的缺口。

定位：`backend/app/features/voice/session.py:62`、`backend/app/features/evaluations/delivery.py:87`、`backend/app/features/training/router.py:372`、`frontend/src/views/ReportView.vue:248`。

建议：在保存时按正式问答创建逐轮转写，关联问题、回答 ID 与时间窗；旧会话从已有消息兼容读取。补一条经过实际上传保存入口的端到端修正与重评测试。

## 2. P1：证据追问与必问题覆盖进度脱节

隔离场次启用证据追问并配置两道固定题。两轮之后，实际只追问了本人职责与方案选择，两个固定题均未发出；会话接口却返回 `questionCovered=2, questionTotal=2`。

原因：回复前已经根据 `planned_question` 增加 covered_count，后续证据分支又选择了不同的问题，没有校验固定题是否真的问出。

另外，普通文字训练的浏览器检查发现：服务器已经覆盖 1 题，页面仍显示 **0/2**。回复接口与前端局部更新没有同步覆盖进度。

定位：`backend/app/features/training/service.py:442`、`:472`、`frontend/src/composables/useTrainingSession.ts:54`。

建议：明确必问题与追问的调度关系，只在实际发出对应题目后登记覆盖；回复返回更新后的进度和关联题目 ID，前端据此同步。验收同时检查“真的问到了”和“页面显示一致”。

## 3. P1：测评及已结束训练的条件没有锁定

复现了两个边界：

1. 新题迁移的提示卡返回 409，但 POST JD 返回 **200**，原来的两道新题被候选人自选的基础题替换。会话仍为 `purpose=TRANSFER`，提示使用仍为 0。
2. 已结束且报告为 VERIFIED 的训练，仍能修改 JD。修改后原报告 ID 与质量状态均未变化，`eligibleForGrowth` 仍为 true。

这会影响独立测评的解释和同条件比较：当前保存的岗位条件可能已经不是产生原成绩时的条件。

原因：`set_job_description`、`clear_job_description` 主要检查所有权，没有限制 FINISHED 或 TRANSFER；训练页仍展示 JD 修改入口。

定位：`backend/app/features/training/service.py:686`、`:728`、`frontend/src/views/TrainingView.vue:128`。

建议：已结束训练保持条件快照；需要换条件时新建训练。独立迁移和固定条件复测同时在前后端禁止改题、改 JD 等辅助入口，不只隐藏提示按钮。若允许练习中修改，也要显式记录条件版本与边界。

## 4. P2：重新开始不继承证据追问策略

复现：原场次 `adaptiveEnabled=true`，结束后调用“同场景重新开始”，新场次变成 `adaptiveEnabled=false`。

原因：restart 复制 mode、depth、channel、JD 等条件，没有传递 evidence_driven，创建函数使用默认 false。

定位：`backend/app/features/training/router.py:287`。

建议：按“沿用原配置重新练习”明确复制训练策略和适用的考察标准版本；如果要切回标准方式，应在界面上说明，而非静默切换。

## 5. P2：样本不足的成绩仍更新个性化能力值

复现：只答一轮，注入有效高分模型响应。报告标为 LIMITED_SAMPLE、eligibleForGrowth=false，但四个 SkillState 的 attempts 均变成 1，能力值也变化。

这里使用合成响应检验数据流，不表示真实模型给该回答打过满分。

原因：更新能力值检查模型可用、证据齐全及非迁移等条件，没有复用正式样本的最低轮次门槛。

定位：`backend/app/features/evaluations/service.py:205`、`backend/app/features/plans/personalization.py:55`。

建议：明确看板与个性化推荐是否使用同一资格口径。若样本不足只能供本次参考，应避免更新长期能力值；若要作为低权重练习信号，应单独记录并解释，不能让它隐含等同正式测评。

## 6. 测试维护问题：四条旧浏览器用例与当前界面不一致

| 失败用例 | 实际原因 |
| --- | --- |
| 场景多题编辑保存 | 测试定位 `.listing .row`，当前界面使用 `.scene-card` |
| 场景题目导入导出 | 在旧 `.row` 编辑入口等待超时，尚未走到实际导入步骤 |
| 微课新增编辑停用 | 新增阶段通过；后续仍定位旧 `.courses .row`，当前为卡片布局 |
| 自评与分享撤销 | 继续等待已主动下线的“生成教练链接”按钮 |

隔离浏览器采用新版场景卡片入口，已完成编辑与保存，确认第一类超时源于旧选择器。上述旧用例应更新，分享断言应按下线范围调整；不能因此宣称导入导出、微课编辑等完整流程已在本轮通过。
