# 人物形象配置与接入记录

## 当前配置（2026-11-28 起：只保留在线数字人）

面试人物只有一条实现：在线数字人（Simli）。本地 Human 3D、照片、Live2D、VRM 回退已全部下线，`frontend/src/lib/avatarConfig.ts`、`lib/live2d.ts`、`PhotoPresenter.vue`、`VrmPresenter.vue`、`HumanPresenter.vue` 已删除，`VITE_AVATAR_PROVIDER` 与 `?avatar=` 覆盖一并失效。微课使用 `CartoonPresenter`（本地卡通老师），不受本次改动影响。

数字人拿不到就**明确报错**，不再静默换形象：

- 开场之前连不上（令牌 503/502、20 秒无画面、WebRTC 失败）：视频面试不开始，房间显示具体原因——后端错误码 + HTTP 状态 + detail，例如「在线数字人未配置：服务端缺少 SIMLI_API_KEY（SIMLI_NOT_CONFIGURED / HTTP 503）」，并给出「重新连接」与「改用语音面试」两个出口。
- 面试中途掉线：不打断已经答完的内容，页面顶部用错误条如实说明原因，画面不再自动恢复。
- 失败原因由 `SimliPresenter` 收集（`lastError()`），`AvatarPresenter` 负责展示与重试，`LiveInterviewRoom` 决定阻塞还是提示。

后端启动统一走 `scripts/start-backend.cmd`（固定 `backend/.venv`），不要用系统全局 Python：依赖不全时会得到一个绑定了端口却不接连接的死进程，前端只会看到 500。

以下保留不同形象接入时的实现与验证记录，其中“当时默认关闭/静态照片”和历史体积/截图数字不代表当前默认状态。当前入口以本节和配置模块为准。

## 本地 Live2D 接入记录

用户因云端计费放弃火山数字人，并确认“免费流畅，接受换成可爱的 Live2D 人物”。视频面试官与微课老师已改为 **Hiyori Momose**。人物在浏览器本地渲染，模型、贴图及 Cubism Core 都随项目前端提供，不需要数字人账号、RTC 凭证或公网人物图片地址，没有数字人按分钟调用费。

原面试语音、识别、大模型与评分继续使用已有配置。人物本地化不代表这些已有语音与模型服务也免费。

本项目使用 Live2D Inc. 拥有版权的 Hiyori 示例模型，并遵循 Live2D Inc. 的使用条款。项目内容由作者自行制作。页面保留人物署名和原有角色设计。

## 人物与声音

- 使用 Live2D 网格、原模型物理设置及自动眨眼，加入克制的呼吸、头部摆动和倾听动作；不是整张 PNG 的放大动画。
- 面试官 PCM 继续由原 Web Audio 播放，人物只读取该播放音轨的音量，不接管、上传或重复播放声音。口型跟随实际播放时刻；打断和结束会清空音轨引用并收口。
- 微课使用已缓存 MP4 的原音轨驱动人物。无需重新生成课程，也不需要等待云端人物进房；暂停、跳转、关闭人物动作会停止说话动作，保留课件原声。
- 口型基于音量控制开合，不能等同于逐音素嘴型。原“重听问题”的浏览器语音后备无法提供音轨，使用说话状态辅助动作；不宣称该后备具有精确口型。
- 人物隐藏到后台时暂停渲染，回到页面恢复；渲染上限 30 FPS，减少动画设置下停止头部、呼吸和眨眼等辅助动作，保留必要的语音口型。
- 人物资源或 WebGL 加载失败时显示恢复入口，面试语音及课件仍可使用。离页释放画布、模型、纹理、观察器和页面事件；暂停课程只停止口型，无需反复下载人物。

## VRM 3D 虚拟人（可选方案，默认关闭）

仓库内提供一套 VRM 3D 虚拟人：three.js 渲染骨骼网格，眨眼与口型由 VRM1 表情 blendshape（`blink` / `aa` / `ih` / `ou`）驱动。当前通过统一配置显式选择，不在默认回退顺序内。

### 开关

- 在前端环境文件设置 `VITE_AVATAR_PROVIDER=vrm`，重启或重新构建后启用。
- 开发/验收可在面试页 URL 加 `?avatar=vrm` 临时启用；生产构建按环境配置走。
- 关闭时页面**不会**请求 `sample.vrm`、`three` 或 `@pixiv/three-vrm`，默认路径与原来完全一致。

### 模型来源与许可

- 文件：`frontend/public/avatars/vrm/sample.vrm`（约 10.3 MB，随仓库提供，运行时不联网）。
- 来源：[pixiv/three-vrm 示例模型 VRM1_Constraint_Twist_Sample](https://github.com/pixiv/three-vrm/tree/dev/packages/three-vrm/examples/models)（英文名 `VRM1_Constraint_Twist_Sample`，v1.0.1）。
- 许可：[VRM 1.0 License](https://vrm.dev/licenses/1.0/) + 模型自带 meta。文件内 `VRMC_vrm.meta` 声明：作者 pixiv Inc.，`avatarPermission: everyone`、`commercialUsage: corporation`、`allowRedistribution: true`、`creditNotation: unnecessary`、`modification: allowModificationRedistribution`。
- 限制：这是 pixiv 供**骨骼/约束测试**用的示例模型，不是角色设计稿；许可以上表为准，但正式商用（尤其对外发行）仍应自行复核 `vrm.dev` 条款与署名要求，本说明不构成法律意见。模型是 T-pose 绑骨，代码里用 `POSE` 常量把手臂放下（约 72°），否则会横在画面里。

### 更换自己的 .vrm

1. 把模型覆盖到 `frontend/public/avatars/vrm/sample.vrm`（或改 `VrmPresenter.vue` 的 `MODEL_URL`）。
2. 只支持 VRM 1.0（`VRMC_vrm` 扩展，由 `@pixiv/three-vrm` 3.x 加载）。VRM 0.x 需先转换。
3. 表情预设需包含 `blink`、`aa`、`ih`、`ou`（缺 `ou` 只是少一层元音混合，不会报错）。
4. 取景自适应：相机距离按 `head` 骨骼世界高度换算（`FRAME` 常量），换人物一般不用调；画面过宽/过窄时调 `HEADROOM`、`FOCUS_DROP`。
5. 体积：模型是静态资源，直接计入 `dist` 体积；10 MB 级模型在本地/内网可用，公网部署建议压纹理或改用 Draco/Meshopt 压缩后的 VRM。

### 实现要点（`frontend/src/components/media/VrmPresenter.vue`）

- 渲染：WebGL canvas 透明背景叠在组件自带的中性灰渐变上（不与深色舞台形成白底方块）。
- 取景：`PerspectiveCamera` fov 22°，焦点落在脖子（头顶留白约 0.1 m），模型居中偏下；头肩构图。
- 光照：暖色主光 + 冷色补光 + 背光轮廓 + 半球环境光，柔和三点布光。
- 待机：呼吸（整体上下 ±4 mm、胸腔 ±0.7°）、每 3–7 s 眨眼一次（闭+开 140 ms，`blink` 0→1→0）、9.5 s 周期头部微摆（±2° 偏摆 + 0.7° 俯仰）。
- 说话：`observeAudio(AnalyserNode)` 取时域 RMS → 0..1（起音 0.15 s、落音 0.07 s 平滑），`aa = level × 0.9`、`ih = level × 0.35`、`ou = level × 0.18 × 慢速起伏`，叠加约 ±1.5° 点头；拿不到音轨时用伪音节包络。
- 倾听：头部侧倾 3°，眨眼间隔 ×1.35。
- 性能：`devicePixelRatio` 上限 2；30 FPS 门控；`document.hidden` / 窗口失焦停止 requestAnimationFrame（回到页面用最后一帧，不会跳时间）；组件卸载 `VRMUtils.deepDispose` + `renderer.dispose()` + `forceContextLoss()`。
- 无障碍：`prefers-reduced-motion: reduce` 下停止呼吸、微摆、点头与倾听侧倾，只保留眨眼与音量口型。

- 模型取舍：两份 fbx 都是全身蒙皮，带 morph 的那份（面部）出场，身体 fbx 只作兜底，避免重叠穿模。

- 待机：胸腔/肩 ±1.6°、整体 ±3.5 mm 呼吸；每 3–7 s 眨眼（160 ms，`AK_09_EyeBlinkLeft` + `AK_10_EyeBlinkRight`）；头部 9.5 s 周期微摆。

- 性能：dpr ≤ 2、30 FPS 门控、`document.hidden`/窗口失焦停渲染、卸载 dispose 几何体/材质/贴图/环境贴图并移除 canvas；`prefers-reduced-motion` 下只保留眨眼。
