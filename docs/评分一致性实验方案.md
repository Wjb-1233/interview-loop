# 评分一致性实验方案

更新时间：2026-11-17。

## 这份文档解决什么

系统给每场训练打四个维度的分：内容与逻辑、贴合问题、信息完整、表达干净。这些分是模型给的，论文里说"模型评分可用"，得拿出证据。证据只能来自同一批回答的两种打分——模型打一遍，人打一遍——然后看两边的排序和分差有多大。

这份文档写清楚抽样、盲评、计算的过程，保证换个人也能重跑一遍。**目前还没有采集真实人工标注，文档里的数值都不能引用。**

## 抽样口径

进正式评分的场次（与成长看板"正式评分"同源，实现见 `backend/app/features/evaluations/quality.py` 的 `formal_filters()`）必须同时满足：

| 条件 | 说明 |
| --- | --- |
| 训练已结束 | `status = FINISHED`，中途退出的不算 |
| 至少两轮作答 | 一轮的样本太少，不给正式分 |
| 中文训练 | 语言为 `zh` |
| 模型评分且非降级 | `degraded = false`，规则兜底分不进入人工对照 |
| 未标记待重评 | `review_required = false`，`delivery.rescoreRequired` 不为 true |
| 非转岗评估 | `assessment_context.purpose` 不为 `TRANSFER` |
| 四维证据齐全 | 每个维度都有证据行：轮次对得上、问话是 AI、回答是 USER、引用是回答里的逐字片段，且理由与练习动作非空 |

抽样在 `backend/scripts/export_annotation_batch.py --blind` 里完成：按 `Evaluation.id` 取候选，用固定种子 20261117 打乱后截取前 N 场。种子固定，所以同一份数据库重跑得到同一批场次。

`--size` 指的是**报告数**，不是行数：一场训练导出 4 行（四个维度），`--size 3` 就是 3 份报告、12 行。取值 1–200。

同一场的四维共用 `group_id`（`evaluation.id` 与评分版本数的哈希前 12 位）。统计时 `score_agreement.py` 会报独立报告数，提醒不要把同一份对话的四行当成四个独立样本——那样会虚高样本量，也会让 Spearman 因为组内一致而被放大。

## 导出与文件结构

```
cd backend
python scripts/export_annotation_batch.py --blind --size 40 \
    --out labels.csv --key-out key.csv
```

导出两个文件，**必须分开放**：

`labels.csv`（交给盲评者的那份）

| 列 | 含义 |
| --- | --- |
| `sample_id` | `group_id` 加维度后缀，例如 `cb3c71699fcd-logic`，是配对用的键 |
| `dimension` | 维度中文名，一行只问一个维度 |
| `conversation` | 整场对话，按业务顺序排成"第 n 轮／问／答"，没有模型分和总分 |
| `human_score` | 留空，等人填 1–5 的整数 |
| `note` | 可选备注，写明打分理由或存疑点 |

`key.csv`（不交给盲评者）

| 列 | 含义 |
| --- | --- |
| `sample_id` | 与标注表一一对应 |
| `group_id` | 报告分组，用于统计独立报告数 |
| `dimension` | 维度中文名，配对时会核对 |
| `model_score` | 模型在这一维度的分（1–5） |
| `model_version` | 当时的模型名，缺记录为 `historical-unknown` |
| `rubric_version` | 评分标准版本，缺记录为 `legacy` |
| `session_id` | 训练 ID，便于回查 |

没有人工分就配不出一致性，所以对照表单独存放；标注表本身不含任何模型数字，避免盲评者被带偏。

## 两人盲评流程

1. 导出后只看 `labels.csv`。`key.csv` 交给第三人保管，或者放另一个目录，标注期间不打开。
2. 两名标注者各自独立打分，中途不讨论、不互相看表。
3. 每行只评一个维度，凭整场对话判断；拿不准就写进 `note`，不要留空分。
4. 打分范围只能是 1–5 的整数。可以填小数，但脚本按数值算，超出 1–5 或非数字的行会被跳过并提示行号。
5. 两人都填完后合并：一致的行直接取该分；差一档的行取两人均值或协商后取整，把差异写进 `note`；差两档及以上的行单独列出来讨论，必要时请第三人裁定。
6. 合并后的表就是喂给统计脚本的 `--input`，行数和 `sample_id` 不能变。

每档的含义建议在标注前统一一次口径（下面这版是建议，正式实验若改动要在报告里写明）：

| 分支 | 分数 |
| --- | --- |
| 明显不达标 | 1 |
| 有明显缺陷，但能听懂 | 2 |
| 基本达标，细节欠打磨 | 3 |
| 达标，几乎没有可挑之处 | 4 |
| 示范级回答 | 5 |

## 计算

```
cd backend
python scripts/score_agreement.py \
    --input labels.csv --key key.csv --report docs/评分一致性.md
```

不加 `--key` 就只能用于早期那种标注表自带 `model_score` 的格式；盲评表没有模型分，必须带 `--key`。

脚本算这些指标：

| 指标 | 看什么 |
| --- | --- |
| Spearman 秩相关 | 排序是否一致。对绝对分不敏感，模型整体给高给低不影响它；样本少于 3 行或某一侧全同分时输出 `None` |
| MAE（平均绝对误差） | 平均差几分，直接反映"敢不敢用这个分" |
| 完全一致率 | 人工分与模型分完全相等的比例 |
| 一档内一致率 | 相差不超过 1 分的比例，比完全一致更贴近实际使用 |
| 偏差 | 模型均分减人工均分，正数说明模型偏松，负数说明偏严 |

除总体外还按维度分行输出，另外附一行独立报告数。

配对时的校验：`sample_id` 在对照表里找不到、`sample_id` 重复、维度与对照表不一致、`model_score` 超出 1–5，这些行都会被跳过，并在输出末尾打印"提示: 第 n 行……"。统计前先看一眼有没有提示，有就回去改标注表，别直接拿报告。

## 怎么解读

- 样本量按报告数算才算数。十几份报告只能说明流程通了，结论要在正式实验的报告数上给。
- Spearman 高但偏差大，说明模型排序能用、绝对值要校准（比如统一减一档）；Spearman 低则说明它在某些维度上根本没抓住评价要点，得改评分标准而不是改阈值。
- 分维度看：常见情况是"表达干净"相关性最高（客观特征明显），"信息完整"偏低（依赖岗位背景）。
- 一档内一致率不到 80% 时，不建议在论文里写"模型评分与人工一致"。
- 报出偏差方向，比只报相关系数更有说服力。
